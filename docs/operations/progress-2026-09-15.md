# Bill Commons progress and product roadmap — September 15, 2026

Bill Commons has a deployed legislative database, public evidence and reliability
surfaces, and bounded Florida/California Scout research. The next product step is
recurring, evidence-backed monitoring. Full autonomous 50-state semantic
intelligence remains an unfinished objective.

## Product roadmap, in order

1. **Observe recurring monitoring over time.** The coordinated schema,
   API/worker/web release and accelerated owner canary are complete. Remaining
   acceptance: observe ordinary elapsed cadence and a real legislative change,
   retain its source evidence, avoid duplicate results, and verify operational
   quota deferral. Create, history, pause/resume and owner isolation have passed
   the bounded production checks.
2. **Make bill retrieval reliable for agents.** Reproduce invalid bill/vote
   argument outcomes, verify search-result identifiers and tool examples, then
   fix the demonstrated contract problem. Acceptance: search → bill → history
   and vote retrieval works from returned identifiers.
3. **Deepen Florida and California dossiers.** Cover official text, actions,
   votes, committees and session documents with source scope and retrieval time.
   Acceptance: a representative reviewed bill set can explain what changed and
   point to retained evidence, while exposing missing material.
4. **Deliver changes into team workflows.** Add opt-in email and signed webhooks,
   deduplication, evidence links and clear account quotas. CRM integration follows
   demonstrated demand. Acceptance: one source change produces one actionable,
   attributable delivery with retry and failure visibility.
5. **Search legislative changes.** Join bills, events, evidence histories and
   monitors around questions such as “what changed in my issue area this week?”
   Preserve jurisdiction and source limitations in every result.
6. **Expand semantic state coverage with benchmarks.** Add representative
   per-state adapters and fixtures, historical audits and an affordable cadence.
   The modeled observation demand exceeds the configured 225-request daily
   source budget; changing cadence requires explicit prioritization and evidence.
7. **Advance governed repair automation.** Broaden the repair corpus, resolve
   live provider validation, add durable worker admission and evaluation records,
   and establish review/promotion/rollback controls before production repair.

These are ordered delivery stages, not promised dates. The immediate commercial
proposition is recurring, explainable legislative change with source proof.

## Measurement

Analyze browser activity, authenticated API use, agent tools, synthetic checks
and crawler requests separately. A large crawler workload is evidence of data
retrieval, not proof of people, subscriptions or product-market fit. Existing
telemetry cannot reconstruct general REST/MCP query text retrospectively.
Track completed research, saved-monitor retention, useful change delivery and
successful discover-to-record workflows. Detailed account and traffic analysis
is retained separately from this public engineering progress record.

## Verification boundaries

Local checks and historical canaries apply only to the revisions and behaviors
they exercised. Publication of this branch is not a claim that every feature
above is deployed. Production releases require exact source/artifact binding,
the applicable review, provider readiness and runtime evidence. Existing workers
with unresolved drain or review gates remain separate release units.
