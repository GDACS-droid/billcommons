# Open States bulk session-CSV schema (derived, confidence: HIGH)

Bill Commons' `openstates_bulk.py` adapter ingests the "Bulk CSV Data"
per-session zip archives Open States publishes at
`https://open.pluralpolicy.com/data/session-csv/` (one zip per
jurisdiction+session, gated behind a free Open States login for the actual
download links).

## How this mapping was derived

The download-index HTML page does **not** publish column-level schema (it's
just a list of "Alabama 2026 Regular Session (updated ...)" links gated
behind login), so the column names below are **not guessed** — they were
read directly from the Open States export source code, which is the
authoritative generator of these exact files:

- `openstates/openstates.org` → `bulk/management/commands/bulk_export.py`
  (the Django management command that writes each CSV via
  `Model.objects.filter(...).values()` / `.values("a", "b", c=F("d"))` and
  `csv.DictWriter` — the dict keys become the CSV header row verbatim).
- `openstates/openstates-core` → `openstates/data/models/{bill,vote,people_orgs,base}.py`
  (the Django models whose fields `.values()` projects when called with no
  explicit field list).

Both repos are public on GitHub; fetched 2026-07-23 via
`raw.githubusercontent.com`. Format is declared "CSV Format Version: 2.1" in
the zip's own `README` file (written by `export_session_csv`).

**Confidence: HIGH for column names/types** (read from source, not
inferred). **Confidence: MEDIUM for "is this still exactly what's being
served today"** — Open States could have deployed source changes since this
was read; hence the defensive-parsing rule below.

## Defensive parsing rule (per BRIEF-wave2.md)

The adapter never assumes a fixed column set is present:
- Every CSV is read with `csv.DictReader` (header-driven, not positional).
- Unknown/extra columns are ignored.
- Missing expected columns leave the corresponding field `NULL` — never
  fabricated.
- A completely absent CSV file inside the zip (e.g. a session with no
  votes) is treated as "zero rows for that entity," not an error.


`export_csv()` skips writing a file entirely when its queryset is empty
(`if not num: return`), so any of the above (other than `bills.csv`, which
gates the whole export — "no bills for {state} {session}" aborts before
writing anything) may simply be absent from a given zip. The adapter must
tolerate missing files.

## Column-by-column mapping

### `*_bills.csv` → `bills` table

Generated by `Bill.objects.filter(...).values("id", "identifier", "title",
"classification", "subject", session_identifier=F(...), jurisdiction=F(...),
organization_classification=F(...))`.

| CSV column | Django source | Type | Bill Commons target |
|---|---|---|---|
| `id` | `Bill.id` (OCD id, e.g. `ocd-bill/<uuid>`) | str | `bills.openstates_id` (upsert key alongside session+identifier_norm) |
| `identifier` | `Bill.identifier` | str | `bills.identifier` (normalized via `billcommons_shared.normalize.normalize_bill_number` → `identifier_norm`) |
| `title` | `Bill.title` | str | `bills.title` |
| `classification` | `Bill.classification` (Postgres array, e.g. `['bill']`) | Python-repr'd list string in CSV | `bills.bill_type` (first element, joined if multiple) |
| `subject` | `Bill.subject` (array) | Python-repr'd list string | `bill_subjects` rows (one per element) |
| `session_identifier` | `LegislativeSession.identifier` | str | matched against `sessions.identifier` to resolve `session_id` (never fabricated — job must be told which `Session` row to target; this column is a cross-check) |
| `jurisdiction` | `Jurisdiction.name` | str | matched against `jurisdictions.name` (cross-check only) |
| `organization_classification` | `Organization.classification` (e.g. `"lower"`/`"upper"`) | str | `bills.chamber` |

Notes:
- Array-typed Django fields (`classification`, `subject`) serialize through
  Django's CSV writer as Python list `repr()` strings (e.g. `"['bill']"` or
  `"['appropriations', 'education']"`), **not** JSON. The parser uses
  `ast.literal_eval` defensively (falls back to treating the raw string as a
  single-element list if it doesn't parse, never raises/fabricates).
- `description`, `short_title`, `status`, `status_date`, `introduced_date`,
  `latest_action_text`, `latest_action_date` are **not present** in the bulk
  CSV bill row at all (Open States' CSV bill export is intentionally
  thinner than its v3 API/JSON — status/dates live in `bill_actions.csv`
  instead). Bill Commons derives `latest_action_text`/`latest_action_date`
  from the max-`order` row in `bill_actions`; `introduced_date` from the
  earliest action if classified `introduction`; everything else stays
  `NULL` from this source (a future T1/T3 adapter may fill it in).

### `*_bill_abstracts.csv` → `bill_documents`/description fallback

Fields: `id, created_at, updated_at, bill_id, abstract, note`.
First abstract's `abstract` text is used as `bills.description` when no
richer description is available from another source; not modeled as its
own table (schema has no `bill_abstracts` table — nearest fit is
`bills.description`).

### `*_bill_titles.csv` → `bill_identifiers`/alternate titles

Fields: `id, created_at, updated_at, bill_id, title, note`.
Not currently persisted to a dedicated column (schema has no
"other_titles" table); skipped in v1, logged at debug level.

### `*_bill_identifiers.csv` → `bill_identifiers` table

Fields: `id, created_at, updated_at, bill_id, identifier`.
Maps to `bill_identifiers.identifier` (+ `identifier_norm` computed the same
way as the primary identifier); `scheme` stays `NULL` (not supplied by this
CSV — Open States' `BillIdentifier` model has no `scheme` field despite
`IdentifierBase` defining one abstractly; only `BillActionRelatedEntity`-style
identifier schemes use it elsewhere, not this table).

### `*_bill_actions.csv` → `bill_actions` table

Fields: `id, created_at, updated_at, bill_id, organization_id, description,
date, classification, order`.

| CSV column | Bill Commons target |
|---|---|
| `bill_id` | resolves the parent `bills` row via `openstates_id` |
| `organization_id` | `bill_actions.organization_id` (nullable FK; only populated if that `organizations.openstates_id` has been seen/upserted — otherwise NULL, never fabricated) |
| `description` | `bill_actions.description` |
| `date` | `bill_actions.action_date` (parsed `YYYY-MM-DD[ HH:MM:SS+HH:MM]` → date only) |
| `classification` | `bill_actions.classification` (array-repr string; first element used, full list preserved as comma-join if >1) |
| `order` | `bill_actions.order` |

### `*_bill_sources.csv` → `source_records` / bill provenance

Fields: `id, created_at, updated_at, bill_id, note, url`.
`url` → `bills.source_url` (first source row for the bill) and a
`source_records` row (`entity_type="bill"`, `source_name="openstates"`,
`source_url=url`, `upstream_id=bill_id`).

### `*_bill_related_bills.csv` → `related_bills` table

Fields: `id, created_at, updated_at, bill_id, related_bill_id, identifier,
legislative_session, relation_type`.
Maps directly to `related_bills.bill_id`/`related_bill_id` (resolved by
openstates id, nullable if the related bill hasn't been imported yet),
`related_identifier`, `relation_type`.

### `*_bill_sponsorships.csv` → `sponsorships` table

Fields (from `RelatedEntityBase` + `BillSponsorship`): `id, created_at,
updated_at, name, entity_type, organization_id, person_id, bill_id, primary,
classification`.

| CSV column | Bill Commons target |
|---|---|
| `name` | `sponsorships.name` |
| `entity_type` | used to decide whether `person_id`/`organization_id` resolution is attempted (`"person"` or `"organization"`; blank = unresolved, name-only) |
| `person_id` | resolved against `people.openstates_id` → `sponsorships.person_id` (NULL if not yet imported — person-import is out of scope for the bulk-CSV bill adapter in v1; `name` is always preserved regardless) |
| `organization_id` | resolved against `organizations.openstates_id` → `sponsorships.organization_id` |
| `primary` | `sponsorships.primary` (CSV boolean `True`/`False` string) |
| `classification` | `sponsorships.classification` |

### `*_bill_documents.csv` + `*_bill_document_links.csv` → `bill_documents`

`bill_documents.csv` fields: `id, created_at, updated_at, bill_id, note,
date, classification, extras`.
`bill_document_links.csv` fields (`MimetypeLinkBase`): `id, document_id,
media_type, url`.

Bill Commons' schema attaches `bill_documents` to a `bill_versions` row
(not directly to `bills`), so document-only entries with no matching
version get a synthetic placeholder `bill_versions` row
(`note="(document, no version)"`, `date=NULL`) created on demand — flagged
via `parser_version`/`license_note` note, never silently dropped. Each
document-link row becomes one `bill_documents` row: `media_type`, `url`;
`extracted_text` stays `NULL` (no text extraction in this adapter — that's
a separate worker per ARCHITECTURE.md's version-diffing pipeline).

### `*_bill_versions.csv` + `*_bill_version_links.csv` → `bill_versions` / `bill_documents`

`bill_versions.csv` fields: `id, created_at, updated_at, bill_id, note,
date, classification, extras`. Maps to `bill_versions.note`/`date`.

`bill_version_links.csv` fields: `id, version_id, media_type, url`. Each
becomes a `bill_documents` row under its parent `bill_versions` row (a
version can have multiple format links — e.g. PDF + HTML — each is its own
`bill_documents` row per the existing schema shape, which ties documents to
versions rather than bills directly).

### `*_votes.csv` → `vote_events` table

Fields: `id, identifier, motion_text, motion_classification, start_date,
result, organization_id, bill_id, bill_action_id, jurisdiction,
session_identifier`.

| CSV column | Bill Commons target |
|---|---|
| `motion_text` | `vote_events.motion_text` |
| `motion_classification` | `vote_events.motion_classification` (array-repr; first element) |
| `start_date` | `vote_events.start_date` |
| `result` | `vote_events.result` |
| `organization_id` | resolved → `vote_events.organization_id` |
| `bill_id` | resolved → `vote_events.bill_id` |
| `jurisdiction`, `session_identifier`, `bill_action_id` | cross-check only, not persisted as separate columns (schema has no matching column) |

### `*_vote_counts.csv` → `vote_events.yes_count`/`no_count`/`other_count`

Fields: `id, created_at, updated_at, vote_event_id, option, value`.
`option` is one of Open States' vote-option enum (`yes`, `no`, `other`,
`absent`, `abstain`, `not voting`, `excused`, `paired`); `yes`→`yes_count`,
`no`→`no_count`, everything else accumulates into `other_count`.

### `*_vote_people.csv` → `vote_records` table

Fields: `id, created_at, updated_at, vote_event_id, option, voter_name,
voter_id, note`.

| CSV column | Bill Commons target |
|---|---|
| `option` | `vote_records.option` |
| `voter_name` | `vote_records.voter_name` |
| `voter_id` | resolved against `people.openstates_id` → `vote_records.person_id` (NULL if unresolved) |

### `*_vote_sources.csv` → `source_records`

Fields: `id, created_at, updated_at, vote_event_id, note, url`. One
`source_records` row per vote event (`entity_type="vote_event"`).

### `*_organizations.csv` → `organizations` / `committees` tables

Full `Organization` model fields: `id, created_at, updated_at, extras,
name, parent_id, jurisdiction_id, classification`.

| CSV column | Bill Commons target |
|---|---|
| `name` | `organizations.name` |
| `classification` | `organizations.classification`; when `"committee"`, also creates/updates a `committees` row (`committees.name`, linked via `committees.organization_id` back to the parent chamber organization referenced by `parent_id`) |
| `jurisdiction_id` (openstates jurisdiction id) | resolved against `jurisdictions.openstates_id` |

## Fields NEVER populated from this source (left NULL, not fabricated)

`bills.description` (unless an abstract exists — see above), `bills.status`,
`bills.status_date`, `bills.introduced_date` (unless derivable from
actions), `people.*` (bulk CSV bill export has no people/legislator roster
file — sponsor/voter names are captured as free text `name`/`voter_name`
plus an *optional* id-resolution against whatever `people` rows already
exist from another source; nothing here creates new `people` rows), and any
column not listed above.
